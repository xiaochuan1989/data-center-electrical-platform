# v2.14.1 规范书逐批结果与失败项保留

2026-10-20。模型写出的适用条件不能在其引用原文中找到时，旧版直接抛出异常，整次提取尚未写入结果区，用户只看见错误和下方人工方案的零数量。

网页整理现逐批保留中间工作稿。单条参数证据错误仅隔离该候选项，继续校验其他参数和设备；候选值、候选条件、模型引用文字和失败原因单独列为“未核验”，不混入已通过证据校验的参数。提示词明确条件必须摘录真实原文，不能推断标签，也不能删除真实限制来通过校验。

复核、网络或取消导致中断时，已通过文字证据校验的参数仍可查看及导出 JSON、HTML、Excel；标为未完成，不声称全文完成或语义复核成功。Excel 增加“未通过校验项”表。全项失败时仍展示有依据的设备与失败明细，不生成虚构参数。

未完成工作稿使用独立缓存 `spec_ai_partial_extractions_v1`，仅在用户勾选本机保存时写入。上次完整工作稿继续使用 `spec_ai_extractions_v1`，不会被失败调用覆盖，可在当前工作稿下展开查看。重新完整成功后移除该来源的旧未完成稿。源文改变时两类旧稿均重新验证并失效。原人工方案和设备数量不自动改变，页面说明它们与 AI 清单的统计范围。

`analyzeSpecSource` 默认严格失败行为保留；网页明确启用 `allowPartial` 与 `onDraft`。完整校验器拒绝未完成状态，未完成校验器仍逐项检查来源指纹、设备和有效参数证据。未完成的模型候选项不能当作已核验参数采用。

验证覆盖截图中的无依据条件、后续参数继续保留、全部候选失败、复核失败、取消、工作稿恢复、旧完整稿不覆盖、源文改变失效及导出隔离。使用合成响应，不调用真实外部 AI，不代表真实模型提取准确率；旧版已丢弃且未保存的模型返回无法恢复，需重新整理。

同时修复重复原文在后续页面出现时被拿到首个匹配页复验的问题，缓存和中间稿按保存的原文位置核对，保留实际页码。
