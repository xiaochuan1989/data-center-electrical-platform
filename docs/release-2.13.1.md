# v2.13.1 模型输出截断修复

2026-10-19，用户报告使用DeepSeek Flash整理规范时，页面显示“模型输出被截断，正在尝试缩小分析片段”后停止。

该提示表示接口返回长度限制，不是内容审核或资料证据被拦截。旧请求统一设置8192 token，未显式配置DeepSeek思考模式；[官方API](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)说明deepseek-flash默认启用思考，finish_reason=length可表示max_tokens或上下文长度限制。截图不足以证明本次具体是哪种预算用尽；原调用未保留token诊断，不能断言模型或OCR有错。

旧重试在片段不足1800字符或达到4层时直接抛出原错误，但原错误文案仍声称“正在尝试”，实际操作已停止。

修复：

- 仅对api.deepseek.com上的deepseek-flash/deepseek-v4-pro使用官方参数：关闭思考、JSON输出模式、16384 token上限。其他接口保留8192及原协议，避免给不兼容的第三方服务强加参数。
- 初始片段6000字符；长度截断后允许继续拆分到600字符或6层，保持重叠和Unicode字符完整。仍不接受截断JSON或跳过失败片段。
- 只有确实重试时显示“正在缩小”；停止时说明阶段、片段长度、拆分层数及接口提供的输出token数，明确未采用不完整结果。
- 保留已导入来源、已有提取结果和方案，无需为了重试重复OCR。

验证使用合成请求/响应，覆盖DeepSeek专用参数、第三方协议不变、不足1800字自动恢复、重试耗尽终态、覆盖和去重。没有读取用户密钥，也没有擅自重发真实客户资料；真实提供商的本次恢复效果仍需在网页重试核对。完整npm回归、Python质量检查及公开构建继续作为发布门禁。
