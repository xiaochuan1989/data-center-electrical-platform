# v2.14.2 规范书真实文件读取与整理修复

2026-10-21。用一份真实 7 页规范书（每页带整页水印底图）在网页实跑 AI 整理，依次暴露 6 处程序侧问题；模型提取本身没有出现数值错误。本版逐一修复，并新增离线基准打分脚本，用同一份人工基准度量每轮结果。

## 修复

1. **水印页不再误走 OCR**（`src/platform/nonstandard-file-reader.js`）。旧规则：页面有一张占面积 25% 以上的图片就整页 OCR 并丢弃文字层；整页水印让 7 页全部走 OCR，±、≤、℃ 等符号面临误识别。现先读取全部文字层，去掉多数页重复的行（页眉/页脚/文字水印，页码数字归一）后正文不足 40 字才因大图走 OCR，保留"文字页眉不能掩盖扫描正文"的原有防护；有大图但文字层完整的页使用文字层，并合并提示一次，可勾选"所有PDF页使用OCR"强制识别。
2. **同一行文字片段不再被插入空格**（同上，`joinPdfTextItems`）。pdf.js 常把一句话拆成首尾相接的片段，旧做法一律补空格，原文与参数值出现"再批量 生 产为 宜"。现同一行、间距不超过字高 10% 的片段直接拼接；表格单元格（间距大）仍分隔；无位置信息时沿用旧行为。
3. **设备名称是归一标签，不再要求逐字出现在引用原文中**（`src/modules/spec-extraction.js`）。规范书常以封面、章节、配置表多个别名指同一设备；提示词要求沿用已识别名称而校验要求名称逐字在本段原文，两者矛盾，曾使整轮停止、参数为 0。防编造改由"证据可定位 + 类型已注册"保证；名称未逐字出现时设备照收并标注"设备名称为AI归纳，原文写法：…"。参数阶段按设备编号对应，回显名称的空格差异不再整轮失败。
4. **设备识别整篇一次完成**（6 万字以内），封面/章节/配置表叫法一起可见；参数整理仍分段，且只向模型提供设备身份字段，不再附带可能位于片段之外的设备证据原文。
5. **页眉页脚处理**。程序识别的重复页眉页脚行作为 `page_furniture` 交给模型；参数值混入这些行（常伴随跨页后半句丢失）时该项转入待核对；模型引用省略了页眉时按跳过页眉定位，证据仍存为原文中含页眉的真实连续片段，跳过正文的引用仍拒收。
6. **语义复核单条隔离**（`src/modules/spec-semantic-review.js`）。复核意见中单条不合规（类型非法、引用不在原文、原生文字冒称 OCR 疑点）此前会让整批复核作废、整次整理停止；现只隔离该条，作为"未通过结构校验的复核意见"连同模型原话与原因在页面和 Excel 展示，不计入已校验疑点。疑点可指向其他批次中真实存在的参数；复核请求附 `ocr_pages`。批次级检查（漏查参数、模型声明未完成）不变。
7. **提取范围**：网页适配说明补充逐条提取概述/定义（★不可偏离定义）、标准符合性（"采用最新现行版本"及逐个标准号）与各类定性要求，不限于设备检查清单；value 须为原文连续文字，不用"；"拼接多处。

## 离线基准打分

新增 `dev_scripts/score_spec_extraction.mjs`（`npm run score:spec -- <工作稿.json>`，需在项目目录执行）。按证据在原文中的位置与人工基准多对多配对，数值记号（正负号、比较符、单位大小写）严格比对，分为命中/需人工看/数值不一致/漏提，并单列基准外、引文无法定位、未核验候选能补上的漏提；进行中或未完成工作稿会醒目提示。可读网页导出工作稿（含未完成稿）及 10-20 原型归档。不判断名称和语义。脚本不含客户数据，基准与报告位于被忽略的 `output/`。回归测试 `dev_scripts/test_spec_scoring.mjs` 已纳入 `npm test`。

## 已知问题

- 同一设备仍可能被识别为多台（本次 3 个别名登记为 3 台）。程序无法可靠区分"同一设备别名"与"同类不同设备"，错误合并会混淆参数，故不自动合并；参数本身不受影响。（v2.14.3 已增加人工"合并设备"，见 [release-2.14.3.md](release-2.14.3.md)。）
- 模型偶尔把多行值用"；"拼接，因不是原文连续文字被转入待核对（第 3 轮的工作/贮藏温度）。
- 读取文字变化会使同一文件的旧缓存工作稿失效，需重新整理；旧工作稿中含页眉的参数值在复验时会被拒绝。
