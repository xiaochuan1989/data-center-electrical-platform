# v2.14.3 规范书 AI 结果：人工合并设备

2026-10-21。v2.14.2 实跑中，同一设备在封面、章节标题、配置表中的不同叫法会被识别为多台（3 个别名登记为 3 台）。程序无法可靠区分"同一设备的别名"与"同类不同设备"，错误合并会把不同设备的参数混在一起，所以不做自动合并，改为由人确认后合并。

## 使用

AI 整理结果中，同一设备类型有两台及以上时，每台设备下显示"确认是同一台设备的不同叫法时，合并到 [设备] · 合并设备"。

- 只列出同类型设备；不同类型不能合并。
- 点击后弹窗确认；合并后可"撤销上次设备合并"（撤销记录只在当前页面，刷新后不保留）。
- 参数并入目标设备，完全相同的条目只保留一份（如各设备都有的"认证要求：文档未明确要求"）；参数内容不改动。
- 目标设备显示"已人工合并的其他叫法"及其原文位置；导出 HTML 同样显示（不含按钮）；Excel 增加"设备合并记录"表。

## 实现

- `src/modules/spec-device-merge.js`：纯函数 `mergeSpecDevices(result, fromId, intoId)`，不修改传入结果（撤销依赖它）。被合并设备的名称、范围与原文证据记入目标设备 `mergedFrom`，整份结果记入 `deviceMerges`；未完成工作稿的待核对参数随之改挂目标设备。
- 语义复核：合并只改变参数挂在哪台设备下，复核意见与已复核参数清单按确定规则改到新的参数标识，重算参数指纹；状态随疑点数量重算。
- 复验：`mergedFrom` 每条记录须与目标设备同类型、名称非空、原文证据与当前原文对应位置逐字一致；合并后篡改参数会因复核指纹不符被拒。合并结果在保存前重新复验，失败则不保存。

## 验证

新增 `dev_scripts/test_spec_device_merge.mjs`（已纳入 `npm test`）：同类合并与去重、复核标识跟随参数、连续合并保留全部叫法、不同类型/自身/不存在设备拒绝、篡改合并记录与参数被拦截、未完成稿待核对项改挂、交互控件仅在页面且仅同类设备出现、导出合并记录。浏览器内挂载结果区用合成结果实测合并与撤销，界面与复核状态正确、控制台无错误。使用合成数据，未调用真实 AI。
