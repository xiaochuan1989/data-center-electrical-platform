# v2.14.7 AI结果采用时由人选品类、按行规则预览降级提示

2026-10-21。

## 背景

v2.14.6 的"采用到人工复核"只对程序预设映射的类型显示（PDU、配电柜类、母线类）。用户整理一份电池开关箱规范书时，设备类型"电池开关箱"不在映射中，没有采用按钮；改用页面上的"按行规则预览 → 提取待复核条款"后，得到 97 条按换行切分的条款，大量是封面、保密声明、目录、页眉、编写人姓名等非技术内容，且不分配设备，实际无法使用。

## 修改

1. **采用时由人选择人工复核品类**（`src/platform/spec-extraction-view.js`）。AI 结果中每台设备都显示"采用到人工复核"及品类下拉（配电柜 / PDU / 智能母线）：已知类型按映射预选，未知类型（如电池开关箱）默认"请选择"并提示可按配电柜复核；未选品类时提示"采用未完成：请先选择人工复核品类"。品类判断由人做，程序不默认把未知类型归入某一品类。数据层 `adoptExtractedEquipment` 不变。
2. **按行规则预览降级**（`src/platform/nonstandard-requirement-view.js`）。折叠区标题改为"按行规则预览（备用：仅在没有 AI 接口时使用）"，展开后红字说明会把每一行（含封面、目录、页眉、人名）登记为条款且不分配设备，建议改用 AI 整理后采用。按钮名称与行为不变，以兼容现有浏览器验证脚本。
3. 采用与合并共用的出错提示前缀按操作区分（此前采用出错也显示"设备合并未完成"）。

## 验证

`npm test`、`npm run test:build` 通过；`test_spec_adoption.mjs` 更新为每台设备可采用、已知类型预选、未知类型默认不选、人工选择品类后可采用、已采用设备不再显示按钮。浏览器内挂载完整页面，用真实电池开关箱 PDF 原文与人工基准参数模拟 AI 结果（提取与校验为真实代码）：未选品类点采用得到正确提示；选"配电柜"后采用 44 条，人工区为"1设备·44条要求"，1 条跨页证据未加入并在提示中列出；控制台无错误。
