# N3 采用方案—配置清单基础版设计

> 2026-10-01：先定稿后实施。父计划：[实施计划](nonstandard-presales-roadmap.md)，沿用[契约v1](nonstandard-presales-contract.md)。本轮为手工可编辑的售前闭环，不等于自动完成非标工程设计或各品类业务验收。

## 共用入口与数据

在现有“非标技术要求复核”入口增加“采用方案与配置清单”，共用同一个独立数据包，不建立第二份要求、方案或BOM缓存。界面名称更新为“非标配电售前方案”，旧view id与独立存储键保持兼容。

- 选择已登记设备，创建/打开其方案；方案不能改设备归属。可保留多个备选方案，输出必须明确选择一个，不跨方案混合。
- 按品类字段注册表生成配置表单，所有值初始未知；可明确点击带入本设备已确认的标量要求，带入后仍是未保存设计输入，不自动采用或确认。
- 编辑方案名称、设计假设、排除项/供货边界及关联要求。要求只能关联本设备；组件也可关联同设备要求。
- 组件逐行编辑用途、名称、功能规格、每套数量、单位、品牌、型号/编码、核对依据、风险和型号状态；空型号/编码/数量保持未知，不默认数量1、不加载目录价。
- 点击“保存采用方案”需原因，原子校验后才更新包与同源清单；未保存编辑保持在页面内，其他要求/数量变更不静默覆盖编辑。切换/重新载入/恢复备份如有未保存编辑，必须确认放弃；未保存期间不允许方案确认或方案导出。
- 已确认方案的任何编辑立即撤销其确认，记录修订；恢复JSON时编辑区重载并清空旧草稿，方案和要求均待复核。编辑值不冒充原文要求。

## 品类与一致性边界

配电柜提供进线/母联/出线组件用途；PDU提供输入/输出接口/保护分路用途，类型必须明确机架或柜式；母线提供母线段/始端箱/插接箱/附件用途。可列同用途多个规格。

组件用途是v1可选兼容扩展，旧组件缺用途视作other。已填配置数量时核对对应用途的每套组件数量之和；数量未知、单位不是计数单位或明细缺失不能确认。母线长度只与单位m的母线段比较。这只是已声明字段与清单的数量一致性，不是负荷、短路、温升、相别或保护配合校核。未填配置字段不自动从BOM推造技术参数。

母线可明确点击“带入当前已生成的母线布局”，只读既有工具的已生成设计快照（非未生成草稿/推荐值），经既有桥接重新计算并保留阻断。新方案不回写旧母线配置；厂家型号均待核对，整套布局的BOM乘以明确设备套数。后续旧母线修改不会偷偷更新已带入方案，必须明确再次带入新版本。

## 输出与确认

预览与Excel/可打印HTML说明每次调用同一个buildPresalesDeliverable结果，保存设备/方案ID与包修订号。输出含采用配置、逐项清单、每套/套数/总量、型号状态、核对依据、关联要求及位置、澄清/偏离、假设、排除项和修订。无价格；无数量时总量保持null/待确认。HTML全部转义，Excel文字单元格不作公式。

本轮检查发现现有Excel CDN不可用，新增清单导出使用本机纯函数写出XLSX，不下载依赖、不改变需求导入解析器。仅支持数值/文字静态工作稿，无公式/宏/外链/价格；≤20MB、≤200000单元格，超过Excel单元格文字上限明确拒绝，不截断原文。结构依据[Microsoft SpreadsheetML文档](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)及[PKWARE ZIP规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)，按包关系与CRC32核验，不把软件写出成功当作客户Excel应用验收。

确认条件沿用契约：要求证据和复核有效、全设备条款关联、无未分配要求、供货边界明确、数量/明细一致、型号有依据、无组件风险。按钮只表示人工复核售前配置，不作“全部合规”结论。未确认可导出醒目标记的讨论稿；未完成的工程校核边界始终保留。正式PDF/示意图联动及完整方案包业务验收留给后续阶段。

## 验收

合成软件测试：三品类字段/用途、跨设备关联拒绝、多规格数量合计、未知与错误单位阻断、设备数量乘算、型号核对约束、编辑失效、JSON兼容、输出同源与HTML注入防护。

隔离浏览器：登记要求→归属/确认→建方案→填组件→保存/确认→导出Excel/HTML/JSON；输入即失效、未保存导出拒绝、切换取消不丢编辑、外部数量/要求修改不覆盖编辑、恢复重新复核、母线只读桥接/阻断，1366/1920/900无溢出，无pageerror及客户内容外发。各新品类真实样例不足时只记软件验收，不代替业务验收。

## 本轮实际结果

基础版已本地接入，六组Node回归、构建门禁、Python13/13及三品类浏览器合成流程通过。早期浏览器在window.XLSX缺失时仍可导出真实XLSX；独立Artifact工具读取三品类导出并渲染。最终复跑于2026-10-01 11:43（北京时间）完成，补验技术要求Excel；Python核验五份合成XLSX的ZIP CRC、XML、数量/未知、原文依据、修订与无公式/宏/外链通过。三个宽度截图已检查。

早期测试出现旧CDN解析组件连接失败；最终新会话依赖加载恢复、控制台无错误，但完整N2文件浏览器验收本轮未重跑，不能据此认定读取稳定性已解决。没有真实非标客户方案验收、完整工程校核、厂家规则或最终Excel/系统打印验收；版本保持v2.11.0，不提交/发布。后续入口与未决项见父计划。
