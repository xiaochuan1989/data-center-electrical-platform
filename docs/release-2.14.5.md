# v2.14.5 规范书只整理电气设备、复核漏查不再停止、表格行提取

2026-10-21。线上 v2.14.4 整理一份 28k 字的 Word 规范书（以暖通设备为主，含 PDU 章节）：识别出 5 台设备、616 项参数，其中暖通类设备占 421 项；通信机柜被套用为"列头柜"；语义复核在约 40 批中因某批漏写参数编号整轮停止；PDU 安全性章节的爬电距离/电气间隙表与试验电压表未提取，交直流共用条款只挂到其中一台。

## 修复

1. **电气整理范围**（`src/modules/spec-extraction.js`、`spec-extraction-view.js`）。网页默认只整理电气设备：注册表 29 类去掉"精密空调""火灾自动报警系统"（`SPEC_ELECTRICAL_TYPES`，27 类）。范围外的已注册类型不登记、不提参数，记入 `outOfScopeDevices` 并在页面列一行"按电气范围未整理"；页面说明整理范围。识别提示词只列范围内类型，并写明不在清单中的设备（暖通、机柜、冷热通道、消防等）不登记、不套用相近类型，IT/通信机柜不是列头柜。语义复核收到 `device_scope`，只检查范围内漏项。模块不传 `deviceTypes` 时保持全部类型；复验仍按完整注册表，旧工作稿不受影响。
2. **复核漏查不再整轮停止**（`spec-semantic-review.js`）。只承认本批内、模型明确列出的参数为已复核；多写/重复的编号忽略；漏写的单独补复核一次；仍漏写的记入 `uncheckedParameterIds`，结果保留为待处理并在页面列出。复验要求已复核与未复核清单恰好覆盖全部参数、互不重叠；人工合并设备时同步改写。严格模式（非网页）仍报错。
3. **表格与共用条款提示**：表格数值行逐行提取（value 取整行、name 写明表头与档位、original_text 从表头到该行）；写明同时适用多台设备的条款（如"交直流PDU"、通用要求、安全性）对每台适用设备分别输出。
4. **数值边界检查保留换行**。判断"是否截取了另一数值"时，原先先去掉全部空白（含换行），表格上一行末尾"≥2"与本行开头"60-300"被拼成"≥260"而误判；原代码按换行切分的意图因此从未生效。现保留换行作边界、定位时跳过换行以兼容跨行值；同一行内真实截取仍拒收。

## 评估后未做

按"同值且在原文同一位置"去重：真实结果中表格同一单元格被模型同时挂到"型号1""型号3"，按位置去重会把这类模型错误藏起来。重复条目可见、不误导，保留。

`npm test`、`npm run test:build` 通过。新增回归：电气范围过滤与范围外记录、识别/复核提示只含范围内类型、不传范围保持全部类型、复核漏查补复核与未复核标记及复验、表格行可通过校验、换行边界与同行截取仍拒。该 Word 规范书的 v2.14.4 结果（5 台设备、616 项参数）在新代码上复验通过。范围过滤与两条提示词改动的真实效果尚待线上重跑。
