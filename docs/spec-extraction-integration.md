## 用户目标

上传技术规范书，自动形成设备清单及各设备参数；人工主要检查结果、处理未知与冲突，不再从逐行原文手动登记全部设备和字段。

## 已检查的实现依据

- 本机 `extract-spec/SKILL.md`：v3.3.0 正式工作流（本次审查后升级）。
- `scripts/codex_analyze.py`：prepare 读取原文并生成上下文；finalize 接收 AI JSON、校验并生成报告。脚本自身不调用大模型，正式分析由 Codex 执行。
- `scripts/ai_prompt.md`、`scripts/device_registry.py`：29 种设备、各类参数检查项、主设备与子组件归属。
- `references/data_contract.md`、`scripts/validator.py`：参数与原文证据校验、未提及及外部引用状态、空结果与无依据参数阻断。
- 当前网页 `src/platform/nonstandard-file-reader.js`：浏览器读取器，无 OCR。
- 当前网页 `src/modules/nonstandard-requirements.js`：按行规则整理，首次不识别设备归属，不是上述正式 AI 工作流。
- 当前网页 `index.html` 的 `callAI`：已有用户配置的模型接口，但当前非标需求入口未调用；现有请求输出上限为 4096 token，不宜直接用于整份长规范输出。

## 目标流程

1. 上传并读取原文，保留来源、页序或段落/表格位置。保留完整原文，不能先按简单规则丢弃可能影响语义的章节内容。
2. AI 建立设备清单、位号/用途与章节范围，同类不同设备保持独立。回路中提到设备名称不能直接新增主设备。
3. 按设备范围及共用章节提取参数、限定条件、范围、比较符号、品牌、接口、试验及交付条款。元器件要求归到正确主设备。
4. 程序验证输出契约、合法设备类型、原文真实片段及参数值与证据的对应关系；无法核验的结果不进入已验证参数清单。
5. 按设备展示参数表，可查看原文证据。未提及、引用图纸、冲突、OCR 来源分别标记。证据匹配通过不等于工程师已确认。
6. 输出结构化 JSON 与便于复核的表格/报告；用户采用后再连接现有配置方案。29 种设备可提取，不等于现有三品类方案引擎能配置全部设备。

## 结果契约与处理边界

- `VERIFIED + DOCUMENT`：参数来自原文，真实连续证据存在，参数值能由该证据支持；浏览器中显示为“原文可核验”，不得显示为“人工已确认”。
- `REFERENCED_EXTERNAL + DOCUMENT_REFERENCE`：原文确有图纸/附件引用，保存引用目标及类型，不填造图纸参数。
- `NOT_STATED + NOT_IN_DOCUMENT`：明确显示未提及，证据为空，不计入真实技术参数数量。
- 无设备、无真实参数、解析失败、JSON 截断、证据错误、未注册设备类型等必须明确报错，不能降级成默认参数或宣称提取成功。
- 整份文档中的不同值先按设备和适用范围分开，不能按最大值或最新日期自动覆盖。
- 保留既有来源、工作稿、已确认条款和 UPS 目录；新提取结果先作为独立候选版本，不静默覆盖已采用方案。
- 标准名称可按原文提取；未经当前官方核验的标准摘要不能自动作为合规风险依据。

## 两种接入方式

| 方式 | 使用体验 | 实现边界 |
| --- | --- | --- |
| 网页直接分析 | 上传后点击 AI 整理，网页直接显示设备与参数 | 复用已有模型配置；明确显示发送目的地及内容范围，点击分析才发出请求。需要分阶段请求、输出完整性检测、来源版本绑定、错误及取消处理；不能把技能文件当成可在浏览器执行的 Python 程序 |
| Codex 分析后导入 | 在 Codex 使用原技能产出结构化结果，再导入网页查看或采用 | 可复用原技能 Python/OCR/证据门禁；网页仍须验证导入结果和原文绑定。网页单独上传文件不会自行触发当前 Codex 会话 |

用户已明确选择网页直接分析。实现复用现有设置中的接口地址、模型和密钥，在用户点击 AI 整理时发出请求；文件上传及本机保存本身不发送。未新增后台或常驻服务。

- 基准通过网页证据门禁；经明确的 TXT 适配（移除重复页眉页脚并保留原始 PDF、网页原文和处理说明），也完成原技能 prepare / AI JSON / finalize JSON 路径。原技能原生 PDF 入口在本机缺少其支持的 Python PDF 依赖，本次没有冒称原生 PDF 入口通过。
- 修补★不可偏离属性的派生、显示、导出及缓存校验；必须有真实标记及文档定义，缺少标记不解释为允许偏离。
- 跨页参数允许只从值中省略至少三页重复出现的页首/页尾行。证据仍保留完整连续原文、字符区间和起止页码，显式标记清理；不能省略中间其他正文来拼接参数。
- 增加电气前缀丢失的拦截；单位大小写、母线与系统电压错用、无依据额定值、★属性篡改均以真实基准做负向检查。公开回归用例仅使用合成数据。
- Excel与JSON基准一致；全套 `npm test`、生产构建和公开构建门禁通过；公开构建额外确认没有本次客户文件名或保密页眉。

验收范围：上述基准由当前 Codex 读取真实资料后编制，再输入证据及展示模块验证。没有调用网页已配置的真实 AI 接口，不能据此给出该接口的自动识别覆盖率、请求稳定性或端到端通过结论。

## 长文与扫描件能力边界

- 长文先识别章节和设备，再按设备及相关共用章节组织提取；每块保留源位置和覆盖清单。返回被截断、请求失败、超上下文时明确标记未完成，不能将局部结果当整份完成。
- 跨块的共同要求和同设备矛盾需要合并检查，重叠片段按证据位置去重，不跨设备随意合并。
- 原技能支持按页检测后仅对扫描/低文字页 OCR，记录 OCR 来源，并用同一份原文哈希保持证据一致。
- 网页当前没有 OCR。若选择网页直接分析，扫描件能力必须另行接入并验收；在这之前明确提示无法识别的页，不能声称已等同复用原技能全部能力。

## 验收要求

- 使用用户选定的真实技术规范书，先核对预期设备清单与关键章节，再检查实际结果；不以合成测试代替业务验收。
- 同文档多个品类、同类多台设备、条件/范围、不等式、设备及子组件归属正确。
- 品牌、主要元器件、接口、试验及交付要求可提取，不只提取几个电气数值。
- 每个真实参数能回查正确原文；未知、未提及及外部引用无伪造数值。
- 请求失败、半份返回、扫描页未识别、证据失配均可见，并阻止“整份已完成”的结论。
- 修改来源使旧结果失效；分析期间切换/替换来源时旧异步结果不污染新资料。
- 现有工作稿、人工复核、方案与导出兼容，公开构建不含真实客户文件或 API 密钥。
