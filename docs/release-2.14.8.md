# v2.14.8 第三方中转接口本机转发、连接失败原因提示

2026-10-21。

## 背景

用户把 AI 接口换成第三方中转站后，"测试连接"报 Failed to fetch。排查：中转站可连通（不带 Key 返回 401），但其 nginx 对浏览器跨域预检一律返回 403，响应也不带任何跨域头，浏览器因此拦截。Codex、WorkBuddy 等桌面程序不经浏览器、不受跨域限制，所以同一个中转站在那里可用。本工具是 GitHub Pages 上的纯前端页面，请求由浏览器直接发出，必须由接口允许跨域（DeepSeek 官方允许）。

## 新增：本机转发（`tools/ai-local-proxy.mjs`、`tools/start-ai-proxy.cmd`）

- 双击 `start-ai-proxy.cmd`（需 Node.js）。首次输入中转地址（原 Base URL），保存到被忽略的 `tools/ai-local-proxy.config.json`，之后直接启动。网页"设置"里 Base URL 改为 `http://127.0.0.1:8787`。
- 安全边界：只监听 127.0.0.1；只转发到所设的一个上游地址（不能指向本机）；只接受本工具网页来源（线上地址与本地开发地址），其他网站与无来源请求被拒；不转发浏览器来源与 Cookie，不回传上游 Cookie；日志只记录时间、路径与状态，不记录 Key 与内容。
- 预检由本机应答并允许私有网络访问（`Access-Control-Allow-Private-Network`）；规范书整理单次请求可能数分钟，转发不设超时，网页取消时中止上游请求；上游不可达时返回带跨域头的可读 502 错误。
- 网页代码无需改动即可使用（接口地址本就允许 http）。

## 改进：连接失败原因提示

"测试连接"（`index.html`）与 AI 整理（`src/modules/spec-ai-client.js` 的 `specConnectionHint`）遇到网络层失败时，直连给出"连不上或接口不支持网页跨域，中转站可用本机转发"的操作提示；Base URL 为本机时提示检查转发窗口与 Chrome 本地网络权限。只匹配各浏览器 fetch 网络失败的文案，读取响应结构出错等其他 TypeError 原样显示，不误报为连接问题。README 增加使用说明。

## 验证

`npm test`（新增 `test_ai_local_proxy.mjs`：上游校验、预检本机应答与私有网络、转发与来源/Cookie 剥离、来源白名单、慢响应、上游故障、日志脱敏、网页侧提示与 TypeError 区分）、`npm run test:build`（`tools/` 不进入公开构建）通过；内联脚本语法检查通过。真实中转站经转发：预检 204、请求转发后中转站 401 带跨域头返回；本地开发页面在浏览器内经转发读到中转站响应；`start-ai-proxy.cmd` 首次输入与再次运行均正常（修正了 UTF-8 括号块解析与空设备写法问题）。线上（公网页面→本机）在 Chrome 中的本地网络权限提示与连通尚待用户实测；测试浏览器因安全策略拦截此类请求，无法代测。
