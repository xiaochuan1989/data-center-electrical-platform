# v2.14.4 规范书设备识别单条隔离

2026-10-21。线上 v2.14.3 用一份 Word 规范书整理时停在设备识别：模型给某台设备填写的适用范围（概括的章节名）未逐字出现在原文中，程序拒收该设备；而设备识别阶段任一设备不合格即整次停止，结果为 0 台设备、0 项参数。

这与 v2.14.2 修复的"设备名称逐字校验"属同一类问题，当时只放开了设备名称，遗漏了相邻的适用范围，也没有把单条隔离做到设备阶段。

## 修复（`src/modules/spec-extraction.js`）

1. **适用范围按归一标签处理**：未在原文中逐字出现时照收，标记 `scopeInEvidence=false`，页面提示"适用范围'…'为AI归纳，原文中未找到相同写法，请核对"。按整份原文判断，整理与复验结论一致。防编造仍由设备证据可定位与类型已注册保证。
2. **设备识别单条隔离**：单台设备候选不合规（证据无法定位、类型未注册等）只隔离该台，记入未完成工作稿的 `rejectedDevices`（模型给出的类型、名称、范围、引用原文与原因），其余设备照常整理与复核；全部不合格时停止并保留每台原因。
3. **参数阶段引用未识别设备**：只隔离该组参数，记入 `rejectedDevices` 并注明未采用的参数数量，不再整次停止。严格模式（非网页）仍直接报错。

页面"未完成工作稿"列出未通过校验的设备候选及原因；Excel"未通过校验项"表增加设备候选部分。复验：完整工作稿不得带 `rejectedDevices`；未完成稿校验其结构与片段范围；`scopeInEvidence` 须与原文一致。

## 验证

`npm test`、`npm run test:build` 通过。新增回归：范围为AI概括写法照收并标记、精确范围为 true、篡改标记被拒；一台不合格被隔离而另一台照常整理与复核；全部不合格停止且保留原因；严格模式仍报错；参数阶段引用未识别设备只隔离该组。浏览器内用合成数据确认页面提示与待核对设备列表。该 Word 文档尚未在新版本上重跑。
